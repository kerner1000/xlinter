# 2026-11-09 - Version 0.4.0

## Version bump

**Scope:** xlinter, branch `chore/2026-11-09-release-0.4.0`, session worktree
`/Users/alex/sources/xlinter.worktrees/vigorous-banach-43ea88`.

**Done:** `package.json` and `package-lock.json` move from 0.3.1 to 0.4.0. No tag is pushed; tagging and
approving the staged package stay with a maintainer.

**Why:** 0.3.1 was never published. npm lists 0.1.0, 0.2.0, and 0.3.0, origin has no tags, and `de83f1b`
(`chore: release 0.3.1`) changed only the version fields. `main` at `39fff29` declared 0.3.1 while
containing the breaking change from PR #22 (`7efaf02`). `scripts/check-publish-source.mjs` requires a
clean HEAD on `main` that tag `v<version>` names; it does not compare the version with the changes it
contains. Tagging `v0.3.1` at the head of `main` would have passed it and shipped the exit 2 change to
`^0.3.0` ranges as a patch.

0.4.0 is also the first version to go through the release workflow from issue #9, which 0.3.1 was meant
to prove.

## Correction to the missing lint path entry

`2026-11-06-132513-missing-lint-path.md` says a 0.3.2 release of the PR #19 change is possible only if
tagged before PR #22 merges. Both parts are wrong. The unreleased number is 0.3.1, and the gate accepts
